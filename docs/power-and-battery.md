# 전력 최적화와 배터리 측정 기록

원시 데이터:
- [`data/battery_raw.csv`](data/battery_raw.csv): `epoch,원시 ADC mV,RSSI`, 약 5분 간격. 보정하지 않은 값이며, USB를 꽂으면 VBUS(약 4.9V)가 기록됩니다.
- [`data/events.json`](data/events.json): 배터리 교체, 펌웨어, 보정 이력

## 1. 펌웨어별 방전 속도

| 기간 | 펌웨어 | 결과 |
|---|---|---|
| 10/7 13:19–16:31 | `tdisplay`: Arduino 단독, CPU 240MHz, WiFi 상시 | **약 -219mV/h, 3.2시간 만에 방전** |
| 10/7 17:19–21:45 | `tdisplay_lp`: 자동 라이트슬립 | 약 -18mV/h |
| 10/8 09:58 → 10/10 02:56 | `tdisplay_lp`, 완충에서 시작 | **완충 1회 41.0시간**(기존 셀 기준값) |

`tdisplay_lp`에서 바꾼 것:
- PlatformIO `framework = arduino, espidf` 하이브리드 빌드
  - `sdkconfig.defaults`에서 `CONFIG_PM_ENABLE`, `CONFIG_FREERTOS_USE_TICKLESS_IDLE`을 켬
  - Arduino 기본 빌드에는 PM이 꺼져 있어 라이트슬립이 불가능함
- `esp_pm_configure`로 CPU 최대 80MHz, 최소 40MHz(XTAL), `light_sleep_enable`
- WiFi `WIFI_PS_MAX_MODEM`, `listen_interval = 10`(비컨 10개, 약 1초마다 수신). listen_interval은 연결 전에만 바꿀 수 있어 `WiFi.begin(..., connect=false)`로 설정한 뒤 `esp_wifi_connect()`
- LCD 백라이트 끔, LCD 미초기화, 블루투스 끔

기존 셀의 용량은 라벨상 2.07Wh(약 560mAh)였습니다. 그런데 충전 중 USB 입력이 약 1W(약 200mA)였고 충전 시간도 그에 맞아서, 실제 용량은 약 200mAh로 추정합니다. 그러면 41시간은 평균 약 5mA에 해당합니다.

## 2. 롱폴링 타임아웃 버그 (10/13 수정)

`HTTPClient::setTimeout(uint16_t ms)` 인자에 `(240 + 20) * 1000 = 260000`을 넣어서 값이 **63392ms로 잘렸습니다.**

- 서버는 최대 240초를 기다리는데, ESP32는 약 63초 만에 응답을 포기하고 새 요청을 보냈습니다.
- 서버에는 버려진 요청이 쌓였다가 뒤늦게 응답했습니다.
- 위 41시간 기록도 실제로는 약 1분 주기로 요청한 조건에서 나온 값입니다.

수정 내용:
- **대기 시간 조정**: `WAIT_SEC = 55`, 타임아웃 65초(65535ms 상한 이내). 연결 단계는 `setConnectTimeout(10000)`으로 제한합니다.
- **자가 복구**:
  - 연속 3회 실패하면 WiFi를 끊고 다시 연결합니다.
  - 20분 동안 한 번도 성공하지 못하면 `esp_restart()`로 재부팅합니다.
  - 철문 밖 약한 신호에서 '연결은 된 것 같은데 통신이 안 되는' 상태로 멈추던 문제(10/13 14:53부터 오프라인)에 대한 대책입니다.
- **진단 보고**: 요청마다 `rr`(esp_reset_reason), `nf`(누적 실패), `ds`(마지막 WiFi 끊김 사유)를 실어 보냅니다. 웹 상단 연결 칩에 마우스를 올리면 보입니다.

## 3. 배터리 전압 측정과 보정

- **USB 연결 중**: ADC에 배터리가 아니라 VBUS(약 4.9V)가 읽힙니다. 그래서 **충전 중에는 잔량을 실측할 수 없습니다.**
  - 서버는 꽂기 직전 전압으로 시작 잔량을 잡고, 시간으로 진행률을 추정합니다.
  - 충전 전류 대비 셀 용량 비율(C-rate)이 작을수록 정전류 구간이 높은 잔량까지 이어지고, 정전압 구간은 길어지는 모델입니다(`charge_profile`).
- **송신 순간 처짐**: WiFi가 송신하는 순간 전압이 수십 mV 처집니다. 그래서 최근 3회 측정의 중앙값을 씁니다.
- **보정 두 가지**(`data/calib.json`):
  - **전압 게인 0.9888**: 멀티미터 3.90V(무부하) 대 ADC 3944mV. 이 보드의 ADC는 약 1% 높게 읽습니다.
  - **만충 기준 4.098V**: 이 보드의 충전 회로는 표준 4.2V보다 낮은 약 4.10V에서 충전을 끝냅니다. 이 값을 100%로 놓고 표준 LiPo 곡선을 늘려 맞춥니다. 완충 후 30분 이상 더 꽂아 뒀다가 뽑으면 자동 갱신됩니다.
  - 처음에는 '만충 = 4.18V'로 가정해서 완충 직후 93%로 표시됐습니다. 이 두 보정으로 해결했습니다.
- **원시값 저장**: 로그에는 원시값을 저장하고 보정은 표시할 때만 적용합니다. 보정을 바꾸면 과거 기록 전체가 다시 계산됩니다.

## 4. 배터리 부족 대비

10/10 새벽 방전 뒤 이틀 넘게 문패가 마지막 화면("재실")을 그대로 띄우고 있었습니다. 이를 막기 위해 다음 규칙을 넣었습니다.
- 최근 3회 중앙값이 **8% 이하**면 서버가 현재 그림 아래에 빨간 띠(`배터리 부족 · 표시가 최신이 아닐 수 있음`)를 덧그려 한 번 더 갱신합니다.
- 15% 이상으로 오르면 띠를 뗍니다.
- e-paper는 전원이 꺼져도 화면이 남기 때문에, 꺼진 뒤에도 경고가 보입니다.
