# 연구실 재실 표시 e-paper 문패 — 핸드오프 문서

작성일: 2026-10-07 / 이전 작업: claude.ai 채팅 세션

## 1. 목적

- 교수 연구실 문 밖(철문 추정)에 네오디뮴 자석으로 부착하는 e-paper 문패를 제작함
- 교수가 연구실을 나가면 방 안의 라즈베리파이(또는 서버)가 이를 감지하여 문패를 "부재"로 즉시 갱신함
- 배터리(LiPo) 구동, 3–4주마다 실내로 가져와 USB-C로 충전하는 운용을 전제로 함
- 반응 속도: 수 초 이내(즉시성 필요) — 폴링형 딥슬립 구조는 기각됨

## 2. 확정 하드웨어

| 구분 | 내용 |
|---|---|
| 디스플레이 | WeAct Studio 4.2" e-paper, 흑/백/적 3색, 400×300, SSD1683, 패널 E042A88 |
| GxEPD2 드라이버 | `GxEPD2_3C<GxEPD2_420c_GDEY042Z98, GxEPD2_420c_GDEY042Z98::HEIGHT>` (동작 확인됨) |
| MCU 보드 | TTGO T-Display 클론(Tenstar), **원조 ESP32**(S3 아님), 1.14" ST7789 LCD 내장 |
| 보드 특징 | LiPo 충전 회로, JST 1.25mm 2핀 배터리 커넥터, 전원 스위치 내장 → 별도 충전 모듈 불필요 |
| 배터리 | 현재 보유 셀 라벨 2.07Wh(약 560mAh 추정, 약 65×16mm, 두께 미확인). 계획은 1100mAh |
| 자석 | 원형 10×3mm 네오디뮴, 다수 보유 |
| 라즈베리파이 | 보유 Pi Zero는 v1.1(무선 없음) → USB WiFi/BT 동글 또는 다른 Pi 필요 |

## 3. 확정 결선 (T-Display 윗줄 헤더 한쪽으로 모음)

| e-paper 핀 | T-Display GPIO | 비고 |
|---|---|---|
| VCC | 3V | |
| GND | G | |
| SDA (MOSI) | 26 | |
| SCL (SCK) | 25 | |
| CS | 27 | |
| D/C | 33 | |
| RES | 32 | |
| BUSY | 37 | 입력 전용 핀 |

- 연결 방식: 헤더 플라스틱 스페이서 제거, 미사용 핀 절단, 남은 핀을 바깥으로 꺾은 뒤 듀폰 암 커넥터 체결(납땜 없음)
- 사용 금지 핀
  - 온보드 LCD: 18, 19, 5, 16, 23, 4(백라이트)
  - 스트래핑: 0, 2, 12, 15 — 특히 BUSY를 GPIO2에 두면 업로드 시 다운로드 모드 진입 실패 발생(이전 결선에서 매번 리셋 버튼 필요했던 원인으로 추정, 현 결선에서 해소 여부 확인 필요)
- 배터리 전압: 원조 T-Display 기준 GPIO34(ADC) + GPIO14(ADC_EN, 측정 시에만 HIGH). 클론은 동작 여부 확인 필요

## 4. 동작 확인된 사항

- 테스트 스케치(`test_epaper.ino`)로 3색 출력 정상 확인함
- `setRotation(0)`이 400×300 가로 기본 방향임. `setRotation(1)` 사용 시 300×400으로 바뀌어 도형이 잘리고 문자열이 줄바꿈되는 문제 있었음
- SPI 재매핑: `SPI.begin(SCK, -1, MOSI, -1)` 후 `display.init(115200, true, 50, false)`
- 3색 전체 갱신 약 15초, 깜빡임 정상. 3색 패널은 부분 갱신 사실상 불가
- 주의: Adafruit GFX 기본 폰트는 ASCII 전용임. 한글 표시는 `U8g2_for_Adafruit_GFX` 등 별도 폰트 처리 필요

## 5. 아키텍처 결정

### 5.1 채택안: 라이트슬립 + WiFi 상시 연결 + MQTT

```
[재실 판정 (Pi)] --publish(retained)--> [MQTT 브로커] --subscribe--> [ESP32 문패]
                                                       <--publish--  (배터리 전압)
```

- ESP32는 WiFi 연결을 유지한 채 자동 라이트슬립으로 대기, 메시지 수신 시 즉시 기상
- 상태가 이전과 다를 때만 e-paper 전체 갱신 후 `hibernate()`
- 브로커: Pi의 mosquitto 또는 연구실 NAS(Synology, Docker) 중 택일 — 미결정
- 토픽 제안
  - `door/status` (retained): `{"state":"away","text":"부재중","until":"15:00","seq":12}` 형태
  - `door/battery`: 주기적 전압 보고, 임계값 이하 시 Pi가 폰 알림(ntfy 등)
- 표시 상태 후보: 재실 / 부재(빨강 강조) / 강의 중 / 회의 중, 복귀 시각. 확장안으로 Google Calendar 연동

### 5.2 전력 관련 필수 사항 (3–4주 목표 달성 조건)

- **자동 라이트슬립 활성화 필수**: `esp_pm_configure()`로 light sleep 활성화. `CONFIG_PM_ENABLE`, `CONFIG_FREERTOS_USE_TICKLESS_IDLE` 필요 → Arduino IDE 기본 빌드에서는 미적용 가능성 있음. **PlatformIO + `framework = arduino, espidf`** 또는 순수 ESP-IDF 권장
  - 모뎀 슬립만 적용 시 평균 20mA 이상으로 수일 내 방전됨
- WiFi: 학교 공용망(WPA2-Enterprise, 브로드캐스트 과다) 지양, 연구실 전용 2.4GHz 공유기 사용, DTIM 3 수준 설정
- MQTT keepalive 5–10분으로 길게 설정
- 부팅 직후 LCD 백라이트(GPIO4) LOW, LCD 미초기화 상태 유지
- 보드 대기 전류(USB-UART, 분압, LDO) 수백 µA 존재 — 감수 가능 수준
- 첫 주에 배터리 전압 로그 기울기로 실제 수명 역산 필요
- 현재 셀이 약 560mAh라면 예상 수명 1.5–2주

### 5.3 기각안 및 사유

- 딥슬립 + 주기 폴링: 수명은 길지만 반응 지연(분 단위) → 즉시성 요구로 기각
- nRF52840 + BLE 저듀티 스캔: 수명 수개월이나 보드 신규 구매·개발 부담 → 3–4주 충전 운용으로 충분하여 보류
- 우노: 5V 로직(레벨시프터 필요), SRAM 2KB 부족
- Pi Zero 직접 구동: 대기 약 100mA로 배터리 운용 불가

## 6. 재실 판정 (Pi 측) — 미구현

- 블루투스로 아이폰 감지는 MAC 랜덤화로 불안정 → 비권장
- 1차안: 같은 네트워크에서 폰의 MAC/IP를 `arp-scan`으로 주기 확인, 미검출 10분 지속 시 부재 판정(아이폰 절전 응답 누락 대비 유예)
- 즉시성 보완: iOS 단축어 자동화(WiFi 연결 해제/위치 이탈 시 HTTP 요청). 단, 이탈 후에는 셀룰러이므로 교내 사설 IP 도달 불가 → ntfy.sh 등 외부 중계 또는 Tailscale 필요
- 수동 오버라이드(버튼, 단축어) 경로 확보 권장
- 판정 지연의 병목은 전송이 아니라 판정 로직 자체임에 유의

## 7. 케이스 (3D 프린팅)

- 파일: `epaper_door_case.scad`(파라메트릭 원본), `shell.stl`(본체), `cover.stl`(뒷판)
- 외형 약 101 × 99 × 18.5mm
- 치수 근거: WeAct 공식 보드 외형도/STEP(기판 91.8×89.8, 장착홀 가장자리 2.8mm·Ø2.8), 패널 사양서(외곽 91×77×1.15, 표시 영역 84.8×63.6, 테두리 좌·우·위 3.1 / FPC 쪽 아래 10.3), 사용자 실측(92×89, 91×77, FPC 좌우 각 35mm)
- 구조
  - 본체: 표시 창(외측 45° 모따기), 장착홀 위치 스탠드오프 4개(M2.5 또는 M2 셀프태핑 5–6mm), FPC 감김부 벽 홈, 우측 벽 USB-C 구멍, 모서리 M2 뚜껑 나사 구멍
  - 뒷판: 자석 10×3 포켓 6개(바깥면), 배터리 울타리, T-Display 위치 가이드
- 뒤에서 본 배치: 좌측 배터리(세로), 상단 중앙 e-paper 케이블 커넥터 공간, 우하단 T-Display(USB 우측 벽, LCD가 뒷판 쪽, 듀폰은 위쪽으로 나감)
- **결선 변경 반영 필요**: v2 케이스는 이전 결선(아래 줄 7개 듀폰 + 37번 1개) 기준으로 듀폰 공간을 T-Display 아래쪽에 잡았음. 현재는 윗줄 한쪽으로 모였으므로 듀폰 공간·T-Display 위치·가이드 재배치 필요
- 출력: 본체는 앞면, 뒷판은 바깥면을 베드에 두고 서포트 없이 출력. 뒷판 STL은 Y 미러 처리되어 있음
- 미확정 실측값: 스탠드오프 높이(패널+테이프 두께, 현재 1.5mm 가정), 배터리 두께(8mm 가정), T-Display USB-C 높이
- 제약: T-Display 전원 스위치가 케이스 안쪽을 향해 외부 조작 불가 → ON 고정 운용
